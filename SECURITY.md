# Security policy

## Supported versions

Security fixes are provided for the latest published Rill release. Users should
upgrade to the newest release before reporting a problem that may already be
fixed.

## Report a vulnerability privately

Please use GitHub's **Report a vulnerability** form in the repository's
Security tab. Do not open a public issue for an unpatched vulnerability.

Include the affected Rill version, macOS version, reproduction steps, expected
and actual behavior, and the security impact. A minimal synthetic test file is
welcome when it is safe to share.

Do not submit copyrighted papers, patient information, personal Reading Notes,
an Obsidian Vault, credentials, signing keys, or other sensitive library data.
If a sample PDF is necessary, create or redact a synthetic fixture first.

Rill is maintained as a small, free project. Reports are reviewed on a
best-effort basis, and a disclosure date will be coordinated after a fix is
available.
